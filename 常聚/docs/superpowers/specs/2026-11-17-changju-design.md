# 常聚 · Gatherly 演示版设计文档

日期：2026-11-17
状态：待用户审批

## 1. 意图与背景

**常聚（Gatherly）**是一个以**熟人组局**为切口的新产品，与搭子计划（陌生人搭子平台）同族不同路。

- **为什么是熟人组局**：熟人组局是每周重复的高频场景，自带信任与冷启动；陌生人搭子平台"找到搭子就走"的留存难题，在熟人场景天然不成立。
- **要解决的核心遗憾**：圈子因"发起者倦怠"而散掉。产品理念：**让圈子不散**——组织不靠一个人的热情，而靠机制；聚会不只是事件，而是圈子的共同记忆。
- **产品路径**：熟人组局工具（高频）→ 记忆银行（沉淀）→ 搭子社区（生长，远期：缺人补位开放招募，需用户基数足够后启动）。
- **当前阶段**：演示 DEMO，用于内部讨论与对外演示；最终形态为微信小程序。

## 2. 品牌

- 产品名：**常聚**（英文 Gatherly）
- SLOGAN：**常聚常伴，圈子不散**
- 气质词："小聚"（邀请文案"小聚一下"）、"张罗"（轮值机制功能名"当值张罗"）
- 产品气质：温情、克制——提醒是思念不是打扰，账本是帮忙不是催债

## 3. 目标 / 非目标 / 反目标

**目标**
- 完整演示熟人圈子的闭环：建圈 → 组局 → 聚会 → 记录 → 复盘（AA）→ 再次组局
- 体现"让圈子不散"理念的四件武器：轮值张罗机制、思念式提醒、记忆时间轴、散场仪式
- 制造演示高光时刻：散场抽签、曲水流觞、年度回顾、随机买单转盘
- 按小程序形态呈现（仿壳），页面结构为真小程序立项铺路
- **主线深做、次线浅做**：主线闭环（建圈→提案→表态→定案→聚会→散场→记录→AA→再组局）与四个武器、四个高光完整可操作；次线功能（模板建圈/空白建圈/顺延/项目待定投票/照片留言等）有入口、能演示到，不做完整深度

**非目标**
- 不做真实后端与真实用户系统（mock 数据 + localStorage）
- 不做联机小游戏（曲水流觞为单机传手机模式）
- 不接微信真实能力（分享、支付、定位均以模拟层呈现）
- 不做陌生人搭子社区（远期规划，不在本 demo 范围）

**反目标**
- 不能做成功能堆砌的页面清单——必须有一条可连贯演示的主线
- 不能把提醒做成骚扰、账本做成催债——温情气质崩坏即失败
- 不能依赖网络——双击 HTML 必须可离线演示

## 4. 约束

- 纯 HTML/CSS/JavaScript，零构建、零网络依赖（沿用搭子计划技术栈与页面模板）
- 375px 宽移动端视口 + 小程序式外壳（顶部胶囊按钮、底部 tabbar）
- 资产复用：本地 tailwind 静态构建、lucide 本地图标、平面清淡主题（dumpling-theme.css 风格）、大转盘组件、北京 mock 数据（搭子计划现有北京商户/活动数据）
- 演示城市北京，一圈一城
- 隐私底线：圈友位置、消费水平仅作推荐引擎输入，**不对任何圈友展示**
- 平台不碰资金流（无支付资质，只做账本与结算清单，转账走微信+手动标记）
- 演示视角：一人"我"视角操作（**"我"=圈主**，建圈人永久角色：改圈子设置/分享卡片），其余圈友为 mock 账号
- **模拟微信外壳**：一页模拟微信聊天作为演示入口（群聊出现常聚卡片→点击进入小程序）；"该张罗啦"等提醒以模拟微信服务通知卡浮层呈现
- **演示控制**：mock 圈子用预置进度快照 + 演示控制（模拟圈友表态、推进到截止时间），机制呈现"正在发生"感但节奏可控，不等真实时间

## 5. 方案选型

| 方案 | 描述 | 取舍 | 结论 |
|------|------|------|------|
| **方案一（选中）** | 仿小程序壳的纯静态 H5 DEMO：移动端视口 + 胶囊/tabbar 外壳，离线可预览 | 优点：最快出活、演示零环境依赖、资产全复用、页面结构与未来小程序 1:1 映射；缺点：代码不是真小程序，立项后需 WXML/WXSS 平移重写 | **选**——DEMO 要的是"看起来、点起来就是小程序"，不是"代码就是小程序"；重写与 UI 定稿合并成一件事 |
| 方案二（弃） | 真微信小程序工程（WXML/WXSS，开发者工具运行） | 优点：交付物即生产雏形；缺点：演示必须依赖微信开发者工具、开发慢一倍、无法离线双击预览 | 弃——对"演示+内部讨论"目的而言成本远大于收益 |

## 6. 已定产品决策

### 6.1 建圈与入圈
- 主路径：**群卡片绑定**——圈主分享小程序卡片到微信群，群友点卡片即自动建圈/入圈（demo 以模拟层呈现此流程）
- 次路径：场景模板建圈（同学/同事/球友/麻将/饭局……）、空白建圈
- **入圈唯一方式 = 点过卡片**，不提供手动补人——保证所有圈友都是可操作的真实用户，投票/轮值等机制才成立

### 6.2 轮值张罗机制
- 每个圈子有一个"**当值张罗**"位；建圈人首任
- **散场时抽签交接下一任**（带仪式感动画）；**抽签范围=全体圈友（含未出席者——没来的人抽中下一位张罗，促进下次出席）**；可"顺延"给下一位（温情处理，无惩罚），**顺延按入圈先后**
- 圈子可设"**聚会节律**"（每两周/每月等）；超过节律系统提醒当值"该张罗啦"
- 提醒走思念路线：附上次聚会的合影，而不是冰冷的数字
- **支持任何圈友发起"想念大家了"人工提醒**
- 当值职责：发起下一场组局提案

### 6.3 组局流程
- **任何圈友都可发起提案**（当值张罗是提醒与责任默认人，不是唯一提案人——保证演示主线在交接后不断）
- 发起人先选大方向（饭局/球局/麻将/户外……）→ 系统**一键生成智能提案**：推荐项目 + 推荐地点 + 默认 3 个时间候选（可自加）
- **时间用矩阵表态**（我可/我不行，自动算最大公约时间）；项目/地点普通投票（支持"随大流"）
- 项目可由张罗设为"待定"让圈友投票
- 投票截止自动定案生成"局"，提醒未表态者；聚会当天提醒 + 地点导航

### 6.4 地点与项目数据
- **城市数据基座**：行政区划（省市区）→ 商圈 → 地点三层；一圈一城，演示城市北京
- **地点库走"合作商户"路线**（复用 v2 merchant-detail 模式，订座权益 + 商业化种子）
- **demo 范围裁切**：只备够提案用的北京地点数据（带区/商圈字段，不做三层行政区浏览 UI）+ 一个简化版商户详情页（订座权益模拟）；POI 导入、AI 清洗补全、商户认领纠错、向量检索均标注为生产期事项，不在 demo 内
- 非合作商户数据：地图开放平台 POI 批量导入做底座 + AI 清洗/归类/补全消费档位 + 商户认领与圈友纠错保鲜
- **向量库前期不上**：规则引擎够用；数据模型预留标签/描述字段，放量后再上混合检索
- 项目推荐依据：圈友共同兴趣 + 避开上次 + 时令；兜底彩蛋"转盘选一个"

### 6.5 聚会记录
- **散场仪式三步**：上传合影 → 抽签交接 → 生成记录卡（时间/地点/项目/出席人/合影/一句话总结）
- 圈子主页"**记忆时间轴**"：每聚一张卡滚动排列，是提醒的素材来源
- 照片按聚会归档，圈友可补传留言；**仅圈友可见**
- **年度回顾**：一年聚了 N 次、去了 M 个地方、首场末场、垫付之王等，类网易云年度报告

### 6.6 AA 账本
- 每场聚会自动关联账本；聚会中随手记 + 散场后补记
- 分账：均摊（默认）/ 按人勾选
- **买单方式三选一：均摊 AA / 随机买单（转盘抽人）/ 指定买单（请客场景）**，买单方式记入聚会记录卡（人情往来可追溯）
- 自动结算 + **债务合并**（最少转账次数方案）
- 平台不碰资金流；三态：待结算/部分结清/已结清；未结清提醒走轻松语气

### 6.7 聚会现场小游戏
- **曲水流觞**（旗舰）：兰亭 IP，**单机传手机**模式——水面流动动画 + 酒杯随机停 + 觞令卡（真心话/大冒险/表演/吟诗），山水水墨视觉
- **大转盘**（复用华熙组件）：聚会场景内容（谁点菜/谁讲秘密/真心话转盘）
- 联机版留真实产品
