# 饺子人格测验表单 — 功能说明（拟定稿）

> 目标：做一个表单页面，用来填写/编辑**人格数据**（测试结果）和**题目数据**（测试题），产出符合 `dumpling-quiz-data.json` 格式的数据。
>
> 数据唯一来源：`dumpling-quiz-data.json`（改完 → `npm run quiz:sync` 同步运行时 → `npm test` 校验）。

---

## 1. 目的与使用场景

| 项 | 说明 |
|----|------|
| 使用者 | 运营/开发（不是 DEMO 的普通用户） |
| 解决的问题 | 直接手改 JSON 容易写错字段、引用错人格 id、破坏 8 人格 4 槽位平衡；表单提供字段级引导 + 自动校验 |
| 产出物 | 一份完整、校验通过的 `dumpling-quiz-data.json`（导入即改、导出即用） |

**建议形态**：搭子计划根目录下的独立离线页 `quiz-form.html`（参考 `activity-manage.html` 的管理页模式，零网络、无需登录），与活动管理页同级的"运营工具"。

---

## 2. 数据模型 ↔ 表单字段

表单字段与 JSON 结构一一对应，**不引入新字段**。

### 2.1 人格数据（personalities，一条 = 一种测试结果）

| JSON 字段 | 表单控件 | 必填 | 校验规则 | 说明 |
|-----------|---------|------|---------|------|
| `id` | 文本输入 | ✅ | 英文小写+数字+短横线（`^[a-z][a-z0-9-]*$`），全局唯一 | 用作人格主键，题目选项的 scores 引用它；已有 id 不可改（改 id 需同步改所有题目引用） |
| `title` | 文本输入 | ✅ | 1~20 字 | 人格标题，如"鱿鱼馅·海王饺" |
| `emoji` | 文本输入 | ✅ | 1~4 字符 | 结果页大图展示 |
| `color` | **下拉单选**（预设 8 组渐变） | ✅ | 只能选预设值 | 见 §6 颜色约束，不允许自由输入 |
| `tags` | 标签动态行（可增删） | ✅ | 至少 2 个，每个 1~6 字 | 结果页标签 |
| `quote` | 单行文本 | ✅ | 1~30 字 | 人设台词 |
| `method` | 单行文本 | ✅ | 1~20 字 | 偷吃作案方式 |
| `description` | 多行文本 | ✅ | 10~100 字 | 人格描述 |

### 2.2 题目数据（questions，一道题 = 1 文本 + 4 选项）

| JSON 字段 | 表单控件 | 必填 | 校验规则 | 说明 |
|-----------|---------|------|---------|------|
| `text` | 单行文本 | ✅ | 1~50 字 | 题干 |
| `options[0..3]` | 固定 4 个选项块 | ✅ | **恰好 4 个** | 页面按 A/B/C/D 渲染（`OPTION_KEYS`），当前 UI 不支持增删选项数量 |
| `options[i].text` | 单行文本 | ✅ | 1~50 字 | 选项内容 |
| `options[i].scores` | **得分行（可增删）**：人格下拉 + 分值数字 | ✅ | 至少 1 行；人格须已存在；分值为正整数 | 数据格式支持一个选项给多个人格加分；当前惯例是每选项只加 1 行、每行 1 分 |

## 3. 校验规则（分三级）

**字段级（实时）**：即 §2 中的各项规则，失焦即提示。

**数据级（导出/保存前）**：

1. 人格 id 全局唯一，数量 ≥ 2；
2. 每道题恰好 4 个选项；
3. 每个 scores 引用的人格 id 必须存在于 personalities；
4. 分值必须是正整数。

**约定级（警告，不阻断导出）**：

5. "槽位平衡"提示：每个题目的 4 个选项应指向 4 个不同人格，且每个人格在全部题目中恰好出现 4 次（当前 8 人格 × 4 槽位 = 32 个选项的设计）。不满足时给出警示文案（如"鱿鱼馅当前只有 3 个槽位"），因为槽位不平衡不会报错，但会导致某些人格永远不可能最高分；
6. 人格/题目数量与计分引擎无关，但页面文案写死了"8 道题"（`dumpling.html` 引导卡、介绍页），增删数量需同步改文案；
7. 导出时 `version` 自动 +1（大改），并在页脚显示当前版本。

## 4. 页面布局（参考 activity-manage.html 风格）

```
┌ 顶部栏：← 返回 | 饺子人格测验编辑   [导入JSON] [导出JSON] [保存草稿] ┐
├ 人格列表（左侧可滚动，卡片式）                                        │
│   每张卡：emoji 预览 + title + id + 编辑/删除 + 新增人格按钮           │
├ 题目列表                                                              │
│   每张卡：题号 + 题干 + 4 个选项块（A/B/C/D 字母角标）                 │
│           每个选项：文本 + 得分行（人格下拉 + 分值）＋ 新增得分行       │
│   新增题目按钮                                                        │
├ 实时 JSON 预览（折叠面板，只读，可复制）                               │
└ 校验结果条：红（字段级错误，阻断导出）/ 黄（约定级警告）               │
```

交互约定（沿用现有项目风格）：

- 所有编辑操作**不可变更新**：改字段 → 生成新数据对象 → 整页重渲染，不用双向绑定；
- 删除人格时，若被任何题目 scores 引用 → 弹确认："该人格被 N 个选项引用，删除后这些得分行将失效"，确认后同时清掉引用；
- 选项文本输入框显示剩余字数（上限 50）。

## 5. 保存与落地工作流

DEMO 是纯离线静态页，**表单不能直接写回仓库文件**，采用：

1. **草稿**：编辑过程中自动存 `localStorage`（key 建议 `dumpling_quiz_form_draft`），刷新不丢；
2. **导出 JSON**：点"导出"→ 校验通过后生成 `dumpling-quiz-data.json` 内容 → 触发浏览器下载（Blob + a[download]）；
3. **落地**（开发者操作，可写进导出后的提示弹层）：
   ```
   1) 用导出的文件替换 搭子计划/dumpling-quiz-data.json
   2) npm run quiz:sync          # 生成 dumpling-quiz-data.js
   3) npm test                   # 一致性 + 引擎 + 页面流程校验，全绿即上线
   ```
4. **导入 JSON**：把现有 `dumpling-quiz-data.json` 粘进来/上传，表单回填，便于改现有数据而非从零填。

## 6. 约束与注意事项（实现时必读）

1. **颜色只能预设下拉**：`color` 是动态拼进 class 的渐变（`from-brand-orange to-brand-yellow`），Tailwind 静态构建只扫描文件内容，任意新组合不会进 `tailwind.css`，除非手动加 safelist + `npm run tw`。预设清单 = 现有 8 组（orange→yellow、pink→red、teal→green、red→orange、blue→teal、green→yellow、yellow→orange、purple→pink）；若要新增组合，需同时改 `tailwind.config.cjs` safelist 并重建。
2. **选项固定 4 个**：`dumpling.html` / `dumpling-test.html` 用 `OPTION_KEYS = ['A','B','C','D']` 渲染，改为可增减需动页面；本期不做。
3. **id 不可改**：题目 scores 按 id 引用人格，改 id = 改主键，表单里人格 id 在"已被引用"状态下应只读；新增人格时才可填。
4. **文案联动**：人格数量/题目数量写死在页面引导文案里（"8道题"、"测测你是哪种饺子人格"、介绍页 teaser 宫格），改动后需同步改 `dumpling.html`、`dumpling-test.html`。
5. **版本号**：JSON 里 `version` 字段，数据有变更时 +1，便于排查线上缓存（页面 script 的 `?v=2` 查询串在数据大改时也应升级）。
6. **零网络**：表单页同样只引本地 `tailwind.css`、`vendor/lucide.min.js`、`style.css`、`common.js`，不调任何接口。

## 7. 验收标准

- [ ] 从零新建：能填出 8 人格 + 8 题，所有字段级校验生效，导出 JSON 通过 `node dumpling-quiz-sync.cjs` 校验
- [ ] 导入现有 `dumpling-quiz-data.json` 回填，字段无丢失，改一处导出后仅该处变化
- [ ] 删除被引用人格 → 确认弹窗 → 引用得分行同步清理
- [ ] 引用不存在的人格 id → 导出被阻断并定位到对应选项
- [ ] 槽位不平衡（如某人格仅 3 个选项指向）→ 黄色警告展示，可导出但明确提示
- [ ] 导出的 JSON 落地后：`npm run quiz:sync` + `npm test`（25 项）全绿，饺子页面与详情页正常
- [ ] 刷新页面草稿不丢；清空草稿按钮存在
